# CLAUDE.md

Instructions for AI agents working in this repository.

---

## What this is

Aegis is a rule-governed XRPL treasury. Spending policy lives in Solidity contracts on Flare Coston2. The XRPL private key exists only inside a Flare Confidential Compute TEE and will not produce a signature unless the on-chain policy authorised the exact payment.

Read `DOCS.md` before writing code that touches contracts, the TEE extension, or XRPL serialisation. Read `PLAN.md` to know which phase is current.

---

## Hard rules

These are not style preferences. Violating them breaks the product's core claim.

**No mocks in committed code.** No mock signer, no fake FTSO price, no stubbed FDC verifier, no simulated XRPL client in any path that a demo or a user touches. Test doubles exist only inside `test/` files and are never imported by `src/`, `contracts/`, `aegis-fce/`, `submitter/`, or `web/`. If something cannot be built against the real thing yet, do not build a fake version — say so and stop.

**No TODO, FIXME, or XXX comments.** If work is incomplete, it does not get committed. Incomplete work is tracked in `PLAN.md`, not in the source.

**No placeholders.** No `0x0000...0000` addresses waiting to be filled, no `example.com` URLs, no `changeme` secrets, no functions that return a constant "for now". Every value in committed code is either real, read from configuration, or derived at runtime.

**No silent fallbacks.** When the FTSO price is stale, revert. When the policy digest does not match, return status `0`. When a treasury is unknown, error. Never substitute a default and continue. Every failure path in this system is a refusal to spend money, which is the correct outcome.

**Never log, return, or persist private key material.** Not at debug level, not in an error message, not in `GET /state`. `/state` returns booleans and sequence numbers. If you find yourself writing a struct field that holds a key and is reachable from a response type, stop.

**Do not weaken a check to make a test pass.** If `MAX_PRICE_AGE` blocks a test, fix the test setup. If the digest check blocks a flow, the flow is wrong.

## The invariant that matters most

`PaymentController` computes:

```solidity
policyDigest = keccak256(abi.encode(
    requestId, treasuryId, destinationAccountId, destinationTag,
    amountDrops, sequence, lastLedgerSequence, feeDrops
));
```

The TEE recomputes the identical digest from the fields it decoded and refuses to sign on mismatch.

If you add, remove, or reorder a field in `SignRequest`, you must change both sides in the same commit and update the decoder registration. A change on one side only produces `policy digest mismatch` on every payment, which looks like a bug and is actually the system working.

## Three-way constant alignment

`opType` and `opCommand` strings must be byte-identical in three places:

```solidity
bytes32 public constant OP_TYPE_XRPL = bytes32("XRPLW");
```
```go
const OPTypeXRPL = "XRPLW"                                  // internal/config/config.go
```
```go
case dataFixed.OPType == teeutils.ToHash(config.OPTypeXRPL): // internal/extension/extension.go
```

A mismatch is the single most common cause of `unsupported op type` and `unsupported op command`. `bytes32("...")` truncates at 32 bytes — keep the strings short.

There are six commands: `KEYGEN`, `SIGNTX`, `STATUS`, and the k-of-n three — `SKEYGN` (this machine's signer key), `MSIGN` (this machine's share of a quorum signature) and `SETUP` (the signer list, then the master key's retirement). `./scripts/check.sh` asserts all six across the three locations, so a drift fails there rather than on a live instruction.

Bump `Version` in `internal/config/config.go` whenever behaviour or the on-chain interface changes. The code version is part of the extension lifecycle and the attestation identity.

## XRPL rules that are easy to get wrong

- Amounts are in **drops**. 1 XRP = 1,000,000 drops. Never let a float touch an amount; use `uint64` and `bigint` throughout.
- Fields serialise sorted by `(typeCode, fieldCode)`, not by name and not by declaration order.
- Omit `DestinationTag` entirely when it is zero. Serialising a zero tag produces a different hash than omitting it.
- Single-sign hash prefix is `0x53545800`. Transaction id prefix is `0x54584E00`. Multi-sign is `0x534D5400` and appends the signer's AccountID, which is what stops a signature collected for one signer being replayed as another's — that path is built and lives in `internal/xrpl/multisign.go`.
- A multi-signed transaction carries `SigningPubKey` as the **empty blob**, not omitted. XRPL reads the emptiness, not the absence, as "authorise against the SignerList", and omitting the field is a different serialisation and a different hash.
- The `Signers` array must be sorted by AccountID ascending; `SignerEntries` on a `SignerListSet` must not be, and the serialiser preserves the order it is given for exactly that reason.
- Hash is SHA-512Half: `sha512` then take the first 32 bytes. Not `sha256`.
- ECDSA signatures must be DER-encoded with a low-S value, and nonces derived per RFC 6979.
- Set `tfFullyCanonicalSig` (`0x80000000`) in `Flags`.
- `LastLedgerSequence` is mandatory in this system. A transaction without one can never be proven non-existent, which breaks the failure path.
- The `Memos` array carries `keccak256(abi.encode(requestId))`. This is what links the XRPL transaction to the on-chain request in the FDC proof. Do not change the encoding without changing `ExecutionVerifier` in the same commit.

## FTSO rules

Feed id is derived, not hardcoded:

```solidity
bytes21 constant XRP_USD_FEED = bytes21(abi.encodePacked(uint8(1), bytes7("XRP/USD"), bytes13(0)));
```

Always check the timestamp. `MAX_PRICE_AGE` is 180 seconds and reverting is correct. Never cache a price across transactions and never fall back to a previous value.

## Testing requirements

Every policy rule needs both a passing and a failing test. A rule with only a happy-path test is not tested.

Required coverage before any phase is marked complete in `PLAN.md`:

- tier resolution at boundary values, including exactly at a ceiling
- rolling window exhaustion, and release after proven non-execution
- allowlist hit and miss, including tag `0` semantics
- proposer self-approval rejection
- duplicate approval rejection
- dispatch before timelock rejection
- stale price rejection
- digest mismatch rejection in the extension, driven by an actually tampered payload
- frozen treasury rejection on every entry point
- XRPL serialisation verified against known-good vectors from the XRPL reference implementation, not against our own output

Extension tests run against real instruction payloads produced by the contracts, not hand-written JSON.

## Conventions

**Solidity.** Custom errors, never revert strings. Checks-effects-interactions. `immutable` for anything set once in the constructor. Named imports only. NatSpec on every external and public function. No inheritance beyond one level.

**Go.** Errors wrapped with `%w` and context. Every mutation of shared state under the mutex. Handlers follow the scaffold pattern exactly: decode, validate, execute under lock, `buildResult`. Never `panic` in a handler; return status `0`.

**TypeScript.** `strict` on. No `any`. `bigint` for all chain amounts. No floating-point arithmetic on money anywhere.

**Commits.** Conventional commits with a scope: `feat(contracts):`, `fix(fce):`, `docs(readme):`, `test(policy):`. One logical change per commit. A change that spans the Solidity/Go boundary is one commit, not two.

## Before you finish any task

1. `forge test` and `go test ./...` both pass.
2. `grep -rn "TODO\|FIXME\|XXX\|placeholder\|mock" --include="*.sol" --include="*.go" --include="*.ts" contracts/ aegis-fce/ submitter/ web/src/` returns nothing outside `test/`.
3. If you touched `SignRequest`, both sides changed and the decoder is registered.
4. If you touched an `opType` or `opCommand` string, all three locations changed.
5. If you touched the ABI, bindings were regenerated.
6. If you touched extension behaviour, `Version` was bumped.
7. `PLAN.md` reflects reality — check off what is done, and if something turned out to be wrong, correct the plan rather than leaving it aspirational.
